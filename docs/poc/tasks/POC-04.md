# POC-04 — 四类订单与可重复演示数据

## 目标
让用户用同一套 Sales Order 界面明确创建四类业务订单。不要四套互不关联的新系统；本期 POC 可按**单张订单一种类型**设计，混合类型订单记未来需求。

## 执行
1. 先使用原生 Sales Order/Item/Customer/Stock/Manufacturing 字段和流程；再评估补充 Sales Order 上可见且有校验的**业务类型**字段（生产、耗材、零部件、服务），不能只写在备注或靠四个命名规则假装支持。优先 Customize Form/Custom Field + 可迁移 fixtures（自有 Frappe app 优先；POC 小脚本亦需重放验证）。
2. 建立 docs/poc/TEST_DATA.md 中的匿名公司、客户、供应商、仓库、员工、产品与原料，全部标 POC 测试性质，成本、税率、货币符合演示公司设置。建立可复用的四类订单，各自至少一张；实际单号写 UAT.md。
3. 耗材/零部件作为库存商品，验证销售单→库存可用/采购补货（必要时）→ Delivery Note 直接交货/库存扣减，严格无 BOM 和 Work Order。
4. 服务使用非库存服务 Item，验证销售订单/服务履约记录可存、查询，默认不建 Stock Entry、BOM、Work Order；如开票触发会计凭证，只限测试隔离 site 并注明。
5. 生产类订单选择产成品 Item/按需 BOM；先能创建、提交且在菜单进入设计生产和订单追踪；**完整制造事务与端到端交付放 POC-05**。
6. 每类分别测试列表检索、订单详情、订单类型筛选、客户、负责人、金额、交期及状态；结果可追溯到真实 DocType。
7. 如果服务不具备独立 Service Order 概念，不必制造不成熟的通用服务模型；本期通过非库存 Item + Sales Order + 备注/履约记录实现，记录缺口，不虚构原生功能。
8. 配置和数据创建方式留可重放脚本或有精确字段的操作步骤，拒绝重跑时重复创建无限订单。

## DoD
- 四类订单均可从 PC 中文页面真实创建、提交、查询。
- 非生产类型不生成制造单据；库存类交货可验证真实库存变化，服务无库存变化。
- 业务类型字段可恢复，单号/截图/报表在 docs/poc/UAT.md、docs/poc/evidence/POC-04-orders.md。
