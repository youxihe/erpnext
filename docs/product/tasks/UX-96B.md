# UX-96B — 销售订单 ↔ BOM 双向关联与显式选用

## 问题（用户线上提出）
用户能从“订单执行概览”看到 BOM 物料，但不了解 BOM 与销售订单在哪里关联，尤其希望从任一方向查看关系。

## 当前源码已证实
- 原生 ERPNext v16 的 `Sales Order Item` 子表存在 Link 字段 `bom_no`，这是**销售订单行级**的显式 BOM 选用位置，不是销售订单表头，也不是必须先创建 Project。
- `Work Order` 有 `sales_order` / `sales_order_item` / `bom_no` 字段。
- 现有 `order_execution.order_summary()` 取行级 `bom_no`，如果为空会**回退物料默认已提交 BOM**参与物料覆盖计算；页面的订单行当前对无显式 `bom_no` 显示“—”，而物料卡可能展示默认 BOM，用户容易误以为“本单已确认 BOM”。
- 现有订单执行概览可从订单点击 BOM，但 BOM 原生页未提供“实际引用本 BOM 的订单”清楚入口。

## 最小实施（优先产品骨架）
1. 销售订单**草稿行**提供明确的“本单 BOM”字段或方便查找的“选择 BOM”操作（复用 `Sales Order Item.bom_no`，须校验 BOM.item 与当前行 Item 一致、BOM 已提交且有效）；另有简单“使用默认 BOM / 复制标准 BOM 形成非标版本”入口可按已存在原生机制引导，不必新写 BOM 引擎。
2. **提交前设计确认**：在订单执行概览的“订单与产品”中显示三个独立概念：产品编码、实际选用 BOM（显式写在订单行）、产品默认建议 BOM（未确认时只作建议）。**不得将默认 BOM 静默冒充确认已选用的订单 BOM**。如本次生产订单未明确选用，允许查询默认建议，但提示“尚未确认本单 BOM”，并避免将其数值当作已确定的采购明细。
3. 已提交订单需要改 BOM 时，明确告知走受控变更/新版本/调整后续工单的操作，不能盲目 `db_set` 修改已经过账的 Sales Order Item 或已领料工单。此次至少实现只读追溯及合规操作指引，不做复杂设计变更流。
4. BOM 详情提供一处“引用关系”：**显式引用本 BOM 的 Sales Order Item**（订单号、客户、产品行、数量、状态）、引用的 Work Order（工单号、生产数量、状态）、可点入对应单据。只有 `bom_no == 当前 BOM` 才算显式引用；商品默认 BOM 不等于所有销售订单都引用它。
5. 如需从标准 BOM 复制生成非标 BOM，支持用 ERPNext 原生 Duplicate/Amend/新建路径，保留默认 BOM 不变。本期无需给每个订单都复制一份 BOM，标准品允许多单共用。
6. 全部列表/反向查询必须按**查看者对目标 Sales Order / Work Order 的真实权限和数据范围**过滤。避免 BOM 页面间接泄露别的客户订单或价格。
7. 不影响四类订单：耗材/零部件直接库存流程、服务类不需要 BOM；继续保留订单执行概览的已有真实单据链接和库存数据逻辑。

## DoD & 验收
- 通过中文 PC 草稿销售订单行**选用 BOM**，保存之后从 `/order_execution` 一键打开；同时从该 BOM 页面反向查看这张订单（数量、客户和状态）。
- 两张标准产品销售订单能共用同一 BOM；一张非标订单可引用独立 BOM，新版本不影响原默认 BOM。
- 未确认 BOM 的订单行显著提示“默认建议，尚未确认本单 BOM”；前后展示一致，不出现“订单行 — / 物料覆盖有 BOM”的误导。
- 从 BOM 反查订单/工单，无权订单不可见；已提交订单修改受控；生产单据链和库存回归 PASS。

- 不重做完整 ERPNext 制造/Project、不做高级 BOM 多阶、替代料、复杂审批。
