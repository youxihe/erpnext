> 决策日期：2026-11-08  
> 建议入库位置：`docs/product/decisions/LIGHT_MANUFACTURING_20261108.md`  
> 项目：`youxihe/erpnext`；工作区：`D:\ERP\erpnext`

## 0. 北极星 / 决策原则

目标仍然是让客户体验 **中文 ERP PC、企业微信 H5、企业微信 AI 机器人** 三个入口，操作**同一 ERPNext Site、同一业务单据、同一身份与权限体系**。客户目前没有正式信息系统，基层生产人员数字化能力有限，因此“**重业务单据闭环，轻生产过程跟踪**”。

- **严格使用系统的角色**：销售（客户/订单）、设计负责人（选成品和 BOM）、采购（缺料/采购单）、仓管（采购入库/领料/成品入库/出库）、财务（发票/付款/收款）、管理（总览）。
- **尽可能简单的角色**：生产人员只需打开“我的生产任务”，记录是否完成、目标日期、异常说明或附件，不要求写 Job Card、工时、工序报工、人工制造成本、复杂排产。
- **真实交易底座不简化掉**：Sales Order、BOM、Production Plan/Work Order、Material Request、Purchase Order/Purchase Receipt、Stock Entry、Delivery Note、Sales/Purchase Invoice、Payment Entry 保留 ERPNext 标准业务与单据号；不另外创造库存/财务账本。
- 交付目前按**整机一次发货**设计；预留 ERPNext 的部分交货能力，但不开发复杂装箱、组件级发货、物流轨迹。
- 不做原料合成药水 MIX；耗材/零部件订单仅直接采购/库存交付；服务订单仅履约记录且默认不自动产生库存交易。
- 非关键问题如特殊发票取消、工序成本、复杂审批、UI 微调等只登记 `docs/product/BACKLOG.md`，等待用户排期；危及真实交易一致性、越权和数据破坏的事项必须以最小保护措施处理。

## 1. 新业务流程与角色责任

```
销售：客户/报价/销售订单（订单行=整机最终交付物，承诺交期）
  ↓
设计负责人：确认成品 Item + 选用/调整 BOM + 必要技术图纸附件
  ├────> 采购：生产计划/物料需求 → 缺料校验 → 采购订单 → 到货
  │                                                 ↓
  │                                             仓库：采购入库
  │                                                 ↓
  ├────> 仓库：按工单生产领料/库存转移  <──────────────┘
  │
  └────> 生产负责人：订单对应生产 Project + 固定 Task 模板
                          ↓
                生产成员仅反馈状态、日期、备注/附件
                          ↓
仓库/授权负责人：核对实物完成 + 正式 Manufacture 完工入库
  ↓
仓库/物流：基于销售订单的 Delivery Note，整机出库、一次发货
  ↓
销售/财务：已交付情况 + Sales Invoice/Payment Entry 或采购付款
  ↓
管理：订单全程进度、缺料/任务逾期/发货风险
```

注意：**任务完成 ≠ 库存入库**；Project Task 与 Work Order 不能成为两套独立的“真实完工数量”。任务报告的是过程，仓库审核的 ERPNext 原生 Stock Entry 才是库存变更凭据。**生产领料不等于实际耗料**：如果采用 `Material Transfer for Manufacture`，只是从原料仓转移到在制仓；提交 `Manufacture` 才消耗在制仓物料并增加成品仓库存。禁止同时无意识地使用 `Material Issue` 以及 `Material Transfer for Manufacture` 对同一批材料重复扣库。具体原生选项要在 v16 POC 验证后固定一种默认路径。

## 2. 建模与页面原则

### 2.1 客户交付物、BOM、生产进度三件事分别建模

- **Sales Order + Sales Order Item**：客户要求交付的整机及数量/交期。最终实际发货使用 Delivery Note，按销售订单行建立关系。第一版是整机一次交付。
- **Item + BOM + Work Order**：设计标准/非标 BOM，展开原材料供需求计划、采购备料、生产领料和完工入库。单层 BOM 可满足就不强行多级；非标修改必须能定位本订单选用的 BOM 版本/编号，避免误改其他订单。
- **Project + Task（优先复用 Project Template）**：固定的生产进度阶段、负责人、目标日期、状态、预警和备注/附件。每张生产类销售订单可建立/链接一个生产 Project；如果同一订单多个整机的情况复杂，先按订单主线汇总、记录边界，后续细化，不得临时多套进度真相。
- **Job Card**：仅在 ERPNext 当前配置中确实必须使用或未来客户需要真实工序报工时启用。当前只保留系统基础能力，不让车间人员操作 Job Card。Workbuddy 要实测 v16 BOM 不配置 Operations 是否可正常完成 Work Order/Stock Entry；不得凭文档猜。

### 2.2 固定生产任务模板

参考客户提供的《生产进度表》，建议首套任务模板包含：
1. 机架焊接
2. 机加工件加工
3. 内钣金焊接
4. 电控板组装
5. 管道焊接
6. 机构件组装
7. 电气组装
8. 外蒙板组装
9. 调整老化

这是示例模板，客户可按实际设备类别修改。每项必须有：任务名、负责人、目标日期、状态（待开始/进行中/完成/异常）、实际完成日期（自动记录为宜）、备注/附件。可选“阻塞原因”。不要强制工时、生产数量、工位、复杂依赖、审批和每个阶段的物料消耗。

预警最小规则：**未完成且目标日期早于今天 → 逾期；未完成且未来 3 日内到期 → 临期**（3 日为配置初始建议）；在 PC 管理视图和 H5“我的任务”里可见，未来机器人复用同一 API。避免把所有任务的完成率硬算成真实制造完成百分比：如展示任务进度，明确是 `已完成任务数 / 总任务数`。

### 2.3 物料准备与库存账务

客户 Excel 中的“内钣金件、机加工件、电器件、线材及辅助材料、外钣金件”是材料准备分类，**不是可下单采购的 BOM 明细**。物料采购需对应 Item/BOM Item 的真实编码、需求量和仓库。第一版材料准备概览可以基于 Production Plan/Material Request/采购到货信息进行汇总，不必开发高级 MRP 或每类的手工完成审批。

仓库/采购要验证的闭环：
`Sales Order → BOM → Production Plan → Material Request → Purchase Order → Purchase Receipt → Work Order → Material Transfer for Manufacture（如采用）→ Stock Entry Manufacture → Delivery Note`。

支付/发票按 ERPNext 原生记录，第一阶段只聚合给销售/财务查看，不单独重建财务台账。**商品实物出库与货物发运必须由 Delivery Note / 原生库存凭证反映**，不要用任务状态当作交货单。

### 2.4 面向用户的菜单和页面

保留已验证的一级顶部 + 二级左侧中文导航：不要反复重构整体布局。优先补一个**订单执行概览**（不是整套 ERP 重做）：
- 销售订单号、客户、整机、数量、承诺交期
- 设计 BOM 已确认/未确认、选用版本
- 物料：缺料、已采购、已入库、领料状态（均来自真实 ERP 单据）
- 生产：固定任务完成数、逾期数、最近异常说明
- 完工入库 / 整机交付是否完成（真实 Stock Entry / Delivery Note）
- 开票/回款基本状态，按角色授权可见
- 可点击跳转到相应原生单据（BOM、Production Plan、MR、PO、PR、Work Order、Stock Entry、Delivery Note）

车间人员只看到“我的任务”，字段少、按钮少，手机 H5 优先于 PC 复杂制造页面。项目负责人可以从订单管理页面一键生成/查看固定任务和风险概览，避免让员工理解“Project/Work Order/Job Card”的全部概念。

## 3. Workbuddy 下一步实施顺序（对接已有 BUILD 队列，不新建平行队列）

**首先拉取真实最新 Git HEAD，阅读现有 `AGENTS.md` / `docs/product/QUEUE.md` / 已完成证据；不得假定 10 月下旬队列仍是 TODO 或随意 reset、强推旧版。** 将本文件作为经过用户确认的新优先级决策写入 repo，更新 AGENTS 与 QUEUE 的相关 *未完成* 项，保留 PASS 与已部署功能，不重置现有进度。按下面顺序持续推进。

### A. 基线与现有产品复核（很短）
- 确认当前 ERPNext v16 Site、中文 PC 导航、现有四类订单、生产库存单据、企微 H5、机器人各自当前真实状态。
- 列清“原生可复用/已实现/缺一个入口或简单配置/确实需要开发”。不要重新做旧 POC，也不重新安装。
- 对现有导航、Project / Task / Project Template / Work Order 配置做最小可用性试验；确认 BOM 无工序可否生产完工，如不支持，说明最小可行替代，不重造生产模块。

### B. PC 核心链路优先（销售、采购、仓库、财务规范参与）
- 使用一个完整的“整机一次交付”样本从销售订单连到 BOM、计划/缺料、采购单、采购入库、生产领料、正式制造完工入库、销售出库/交货、销售发票/收款。
- 验证原生各张单据的关联是否明确、点击可到达，订单级汇总的最低页面可用；不把旧 POC 的已有业务能力再开发一次。
- 采购负责人、仓库管理员、财务、销售分别使用自己的账号执行至少一个关键动作，测试越权拒绝。

### C. 固定生产进度（最小增量）
- 基于原生 Project Template + Task 优先实现“一生产类订单 → 一个生产进度项目 → 九个默认任务”；页面是简单中文任务列表，不依赖 Job Card 报工。
- 生产经理/设计负责人设置负责人和目标日期；生产成员更新本人任务状态及备注/附件；系统计算临期/逾期。
- 进度状态变化不会自动提交 Work Order/Stock Entry、不会增加或减少库存；仓库通过正式制造业务办理完工入库。
- 如果已存在相近功能，优先调整菜单/权限/任务模板，而非新建重复 DocType。

### D. 三入口接力（不要等全部 ERP 细节完善）
- 已有共用 API 则补 `orders.summary`、`production.tasks.mine`、`production.tasks.update`、`materials.shortage`，返回正式 ERPNext 引用和明确授权身份。
- H5 最重要的生产功能是“我的任务：状态+日期+备注/附件”，销售查看订单/交付，采购/仓库可查业务单据，继续复用现有企微身份体系。
- Bot 优先回答“这张订单到哪个阶段？”“有哪些任务逾期？”“还缺哪些物料？”；后续再接客户报备和 Excel 操作，使用原来预览→确认→幂等→正式单据的安全方式。
- H5、Bot 和 PC 保持同一 ERP Site、同一身份/权限；有真实企微信息时才标真人 UAT PASS。

## 4. 本轮验收（大模块完成，不做无止境精修）

1. **销售**：创建生产订单，选成品/交期，可查看整机订单执行概览，耗材/零部件直发货、服务不触发库存与工单。
2. **设计**：选择/调整 BOM；本订单选用 BOM 明确；可一键创建/查看固定生产进度项目和任务。
3. **采购**：从 BOM 明细看到真实缺料，创建 Material Request/PO；仓库以 Purchase Receipt 入库，库存增加，来源可追溯。
4. **仓库**：按 Work Order 领料、记录制造完工入库、用 Delivery Note 整机发货；物料/成品仓增减无重复扣账。
5. **生产**：至少两名不同成员更新固定任务状态、备注/日期，目标日期过期后展示预警；无需 Job Card、工时或工位操作。
6. **财务**：通过原生销售发票、收款与采购付款查看订单财务进度，避免深入复杂会计规则。
7. **三入口**：PC 更新任务 → H5 和 Bot 查询一致；H5 更新任务 → PC 可见；Bot 可读同一订单的缺料/逾期情况；权限负例通过。
8. **交付**：整机完工后经仓库实物确认与正式库存单据入库、再经 Delivery Note 出库；生产任务全完成本身不会导致自动完工入库。

最终提交：最新业务流程图、单据链关系、可运行 URL、测试账号安全交接、真实单号/库存前后数值、短视频或截图及一页 UAT。以业务链路是否可演示作为完成标准，不以“新写代码量”衡量。

## 5. 用户后续向客户确认的问题（不阻断 Workbuddy 第一阶段）

- 九项任务是否所有设备都适用，哪些设备需要不同模板？
- 生产任务由谁排定目标日期、由谁更新状态、由谁处理逾期/异常？
- 设计的 BOM 是标准模板复用多，还是经常一单一改？是否有一份能确认物料编码、数量的真实样本？
- 仓库目前是否有明确原材料仓与成品仓、领料记录由谁做、成品最终由谁验收？
- 合同最终交付物是否总是一台整机，是否偶尔会有随机配件、安装服务单列？

默认按：**九任务模板可配置、生产负责人排日期、本人更新状态、仓库执行正式库存、整机一次交付、标准 BOM 优先，非标 BOM 按订单另版** 开工；若客户事实不同，再以配置和小范围定制修正。

## 6. 严禁事项

- 不把 Task/ToDo 的完成直接当“生产完成”或过账；不让生产人员填复杂 Job Card/人工成本。
- 不把材料准备分类当成可采购的物料编码；不因“全部任务完成”自动扣库存。
- 不新建重复 ERP 库存与财务数据库、不改原生总账引擎、不重写完整 PC。
- 不为了发票取消、工时费率、流程花样、UI 打磨暂停企微 H5 与机器人主线。
- 不擅自清理/覆盖原 POC 数据库、JSH ERP、OpenClaw 或真实企业生产环境。
- 当前公开测试环境曾使用多个账户的共同密码：优先安排每账号独立密码、限制管理员外网使用；不要在代码仓库传播旧凭据。
