## 0. 一句话结论

- 把「客户报备（原生 Lead）→ 正式客户（原生 Customer）→ 销售订单（原生 Sales Order）」做成了**能在界面上点完的一条线**：
  客户中心双列表 → 报备详情「转为正式客户」→ 客户详情「新建销售订单」（预填客户）。
- 客户详情第一屏固定展示 **首次报备人 / 首次报备时间 / 当前客户负责人 / 来源报备 / 关联销售订单**；
  Desk 的 Lead、Customer 表单也补了同名按钮，两个入口都能走通。
- 没有建第二份客户表、没有复制 `make_customer`、没有 `ignore_permissions`：全部复用 ERPNext 原生 DocType 与权限。
- 真实账号验收：**本地 38/38 + 浏览器 16/16**，**线上 38/38 + 浏览器 16/16**；

## 1. 产品决策与复用（不建重型 CRM）

| 环节 | 用什么 | 说明 |
|---|---|---|
| 客户报备 | 原生 `Lead`（`lead_owner` = 报备人） | 沿用 BUILD-40/H5/Bot 的 `report_customer`，接口契约不变 |
| 转正式客户 | 原生 `Lead → Customer`，复用 `erpnext.crm.doctype.lead.lead.make_customer` | 只用它的字段映射；不复制、不改框架源码 |
| 报备标记已转 | 原生 `Customer.update_lead_status` | 保存 Customer 时自动把 Lead 置 `Converted`，并回链 Quotation/Opportunity |
| 客户归属 | 新增两个 Custom Field：`custom_first_reporter`、`custom_first_reported_on` | 原生没有同义稳定字段；`owner` 是系统创建人、`account_manager` 会随调岗变化，都不能代表首次报备人 |
| 当前客户负责人 | 原生 `Customer.account_manager`（Link/User） | 由管理人员调整；中文标签改为「当前客户负责人」 |
| 来源报备 | 原生 `Customer.lead_name`（中文标签改为「来源报备」） | 由转换流程自动写入，不另建同义关系字段 |
| 销售订单 | 原生 `Sales Order`，`customer` 关联 | 一客多单，不限制"一张报备一张订单" |
| 商机/报价 | 原生 `Opportunity` / `Quotation` | 保持可选，不强制经过 |

**没有做**：独立 Frappe CRM 安装、商机漏斗、报价审批、客户保护期、销售提成、客户合并、数据大清洗。

## 3. 数据模型与回填

新增字段（补丁 `cn_mfg_poc/patches/v0_0_7/setup_crm_fields.py`，幂等，已注册到 `[post_model_sync]`）：

| 字段 | 类型 | 位置 | 说明 |
|---|---|---|---|
| `Customer.custom_first_reporter` | Link → User，只读 | 第一屏「区域」之后 | 首次报备人（业务归属），不随负责人调岗改变 |
| `Customer.custom_first_reported_on` | Datetime，只读 | 紧随其后 | 首次报备时间（Lead 的首次报备时间或直接建客户时间） |

同时改了三个中文标签（Property Setter，不动字段类型）：`Customer.account_manager` → 当前客户负责人、`Customer.lead_name` → 来源报备。

写入规则在 `hooks.py → doc_events.Customer.before_insert = cn_mfg_poc.crm.set_first_reporter`，
**任何入口（Desk 表单 / 门户 / REST / 脚本）建客户都会执行**：

- 来自报备：报备人 = `Lead.lead_owner`（存在且启用），时间 = `Lead.creation`；
- 直接建客户：报备人 = 当前会话用户，时间 = 当前时间；
- 已有值不覆盖；`Lead.lead_owner` 失效时退回当前用户，不写入无效用户；
- **永不使用 `owner` / `modified_by` 当业务报备人**，也不接受客户端传"报备人"参数。

## 4. 后端契约（`cn_mfg_poc/crm.py`）

| 方法 | 类型 | 权限 | 幂等 / 行为 |
|---|---|---|---|
| `crm.lead_list(q,status,limit)` | GET | Lead read | 返回报备人姓名、状态、关联客户、同名客户、`can_convert` |
| `crm.lead_detail(name)` | GET | Lead read(doc) | 详情 + 是否可转 + 已有同名客户及其负责人 |
| `crm.convert_lead(lead)` | POST | Sales 角色 + Lead write + **Customer create** | 已转 → `replayed=True` 返回原客户；有同名正式客户 → `created=False` 返回该客户，**不合并、不改归属**；否则原生映射建客户并把 Lead 置 Converted |
| `crm.create_customer(name,contact,mobile,note)` | POST | Sales 角色 + Customer create | 同名客户 → 返回已有；有未关闭报备 → 返回 `existing=lead` 提示先转客户；否则建档并写报备人=当前用户 |
| `crm.customer_list(q)` | GET | Customer read | 报备人/时间、负责人、来源报备、订单数 |

| `crm.sales_order_new_url(customer,business_type)` | GET | — | 只返回 `/desk/sales-order/new?customer=…`，不写数据 |
| `crm.customer_center()` | GET | Lead 或 Customer read | 首屏统计与按钮可用性 |

保留未动：`api.report_customer`、`api.search_customers`（H5/Bot/PC 共用合同），签名与返回结构完全一致。

## 11. 未覆盖 / 已知限制

1. **DATA_SCOPE_GAP 未改变**（沿用 UAT-97R 结论）：销售-A/B 在 Desk 列表与客户详情里仍能看到对方客户/订单，这是原生 DocPerm 的现状；本轮**没有**扩大可见范围，也没有偷偷加 `if_owner`。要真隔离需用户确认后单独做。

4. 直接建客户遇到同名未关闭报备会被引导去"转为正式客户"，这是有意设计，避免同一主体两条记录。
5. 客户详情里的订单状态做了中文映射，但 ERPNext 原生更多状态（如 On Hold 细分）仍以 `title` 保留英文原值。
