# UAT-99 — 用户本人操作 ERPNext 完整业务链 V1

状态：WAITING_FOR_USER。由用户亲自按下面步骤在 UAT-98 的独立干净 Site 执行。Workbuddy 可以记录证据、解释页面、修关键阻断，但不代用户执行后标通过。

## 必需的业务范围
销售、设计选 BOM、采购需求与公共库存、合并采购、采购入库、独立生产工单、工单领料、九阶段进度、正式制造完工入库、整机一次出库、采购/销售发票和收付款、库存价值/工单材料成本。企微组织 + H5 + OpenClaw 真人联调在本轮人工 ERP UAT 后推进。

## 样本
同一种标准 BOM：ASSY-X1 每台 RACK 2、SENSOR 1、FASTENER 4。
销售单 A：ASSY-X1 ×2；销售单 B：ASSY-X1 ×1，客户、交期不同；每单显式确认 BOM 并单独建 Work Order。初始原材料仓 RACK 1、SENSOR 10、FASTENER 30；RACK 总需求 6、总需采购 5，另外两项库存充足。该 1 件旧库存没有按单预留，不得假称已锁定。
全程记录真实新站单据编号，而不是沿用旧 d.urlxl.cn 编号。

## 每个岗位的操作
1. 销售王明：从中文版 PC 新建 A/B 两张生产销售订单，录入客户、金额、交期、明确选择本次 BOM 并提交；确认默认建议 BOM 不等于已确认。
2. 设计/生产经理刘工：分别从两张 SO 创建九阶段 Project/Task，设置负责人、计划日期和一项逾期/异常；建立两个独立 Work Order，不能把两张 SO 合并成同一张工单。已完成 Task 不得自动改变库存。
3. 采购员：用两个 SO 的 BOM 需求和共用仓现存库存确认缺 RACK 5；用原生 Material Request 组织需求，一张采购订单可以从多个 MR 来源拉入多条明细（相同 SKU 可保留两行来源）；不强制压成一个采购明细而丢掉引用。核对未收货数量以及重复采购风险提醒。
4. 仓库张工：从 PO 分两次真实采购入库，比如先3后2，Stock Ledger 核对 RACK 1→4→6，待收 5→2→0；禁止另做不关联 PO 的重复收货。采购成本不同的情形要在后续加购/样本中验证 Moving Average，不靠简单价格字段口算冒充过账成本。
5. 仓库：按独立 WO 分别领料，A 领 RACK4/SENSOR2/FASTENER8，B 领 RACK2/SENSOR1/FASTENER4；核对原料仓减少、WIP 增加、Stock Entry.work_order 与原销售单可以回溯。不能把领料转移重复算成耗料成本。
6. 车间李工等：只操作本人九阶段 Task 状态/备注/目标日期；负责人/逾期预警清晰；全任务完成前后原生 Manufacture 未提交时成品仓仍零。
7. 仓库：对两个 WO 分别提交 Manufacture，核对原材料实际消耗、WIP 减少、成品仓增加2+1；再依据两张 SO 各出一张整机 Delivery Note，核对成品仓与已交付量。
8. 财务周会计：分别查看正式采购发票/应付、销售发票/应收与收款，核对 GL 和余额；检查两张 WO 的实际材料成本是否由 Stock Ledger 交易估值生成。明确工单实际材料成本与出库 COGS 可能不同，不把合并计划比例估算当真成本。
9. 三种非生产类订单回归：耗材/零部件直接交货、服务不出库，每类一笔即可。不同岗位用非管理员真实登录提交本岗位原生单据、越权拒绝、重复提交不重复过账、重启后数据完整。
10. 汇总你亲自看到的 UI 易用性：哪一步找不到入口、是否必须先了解 ERPNext 概念、错误提示能否理解、哪些需进入下一阶段 H5/机器人代理操作。
